# Shared-runtime wake experiment

Tested 24 September 2026 with bundled `codex-cli 0.154.0-alpha.6.2`. This is evidence for the local protocol, not a completed desktop rollout.

## What passed

`dev/probe-codex-shared.mjs` starts an app-server on a private Unix socket in a disposable directory and connects two clients. It never connects to the desktop socket, changes settings, or resumes an existing desktop thread. The only durable thread it creates is archived on completion.

- Both clients reported the same server PID.
- A viewing client created a thread. A second client found it in `thread/loaded/list` and started a turn without resuming or subscribing. The viewer received the full turn and final answer. The waking client received status changes only.
- With the waking client unsubscribed, a command approval reached the viewer alone. The viewer declined it; the model acknowledged the decline without retrying.
- When the waking client explicitly resumed the same loaded test thread, there was still only one loaded copy, but **both subscribers received the next approval request**. The viewer declined it and the waking client sent no response.
- After restarting only the private server, the test thread was unloaded and `turn/start` failed with `thread not found`. After the viewer restored the thread, the unsubscribed client could wake it again.

The saved run is [the protocol report](evidence/codex-shared-probe.json). Four model turns completed in the final run; the unloaded-thread attempt failed before starting a turn. The harmless test command was declined both times.

## Implementation constraints

1. A wake client must stay **unsubscribed**. It must not call `thread/resume` or use the existing headless `CodexClient`, which automatically declines approval requests. Normal approvals belong to the native host.
2. Verify that the desktop and wake connection use the same runtime before enabling a binding. A daemon socket or matching version alone does not establish this. The native join command can compare its process ancestry with `server/diagnostics.process.id`; the current shell's ancestry reaches the private desktop Codex server.
3. Only wake a loaded, idle native thread. Do not load an absent thread through a second runtime or use this as a silent substitute for opening it in the desktop app. `turn/start` can steer an active turn; check the active-turn race and queue APIs before production delivery.
4. Keep the room inbox and explicit receive acknowledgement. A lost wake response must not cause a duplicate turn; reconcile or mark the wake uncertain.
5. If the runtime disappears after Astra has gone idle, an attached listener does not magically restart. Preserve the inbox and show that the person must reopen/reconnect the chat or start listening. Claim automatic fallback only when a live listener actually exists.
6. Desktop attachment, native permission presentation, background/hidden-chat subscriptions, restart behavior and version compatibility still need a native end-to-end check before enabling the feature for real rooms.

No ChatGPT relaunch, default daemon start, launch agent, environment flag or Codex setting change was made by this probe.

## Reproduction

The opt-in probe uses the `ws` development library. With it resolvable locally:

```sh
node dev/probe-codex-shared.mjs --run
```

Alternatively pass `--ws-module /absolute/path/to/module.js` for a module exporting the WebSocket class directly or as `ws`. The bundled workspace Playwright `lib/utilsBundle.js` exposes `ws` and was used for the recorded run. No dependency was added to Semaphore.

The Unix socket needs a WebSocket handshake with compression disabled (`perMessageDeflate: false`). Plain JSON lines through `app-server proxy` did not initialize; the proxy carries socket bytes and is not itself a JSONL protocol adapter. A default `ws` compression offer was rejected by this installed server.

Protocol reference: [official OpenAI app-server documentation](https://learn.chatgpt.com/docs/app-server). The schemas generated by this installed binary were also inspected; the observed behavior above is from the local experiment.
