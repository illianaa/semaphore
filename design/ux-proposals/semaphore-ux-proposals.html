Principles

Five principles shape all three proposals

1

One place to start, one message to send.

Starting a group chat should feel like starting any chat.

2

The plumbing stays out of sight.

No setup commands for you to manage. Claude and Astra handle the protocol.

3

You can always tell whose turn it is.

Status claims only what Semaphore can prove: waiting, received, replied.

4

Speak anytime, and pick who replies.

Even while an AI has the stick. Choosing who replies first stays everywhere.

5

Typing feels like the apps you know.

Enter sends, the box grows as you write, and the text is easy to read.

9

Proposed send-anytime contract: append each human message to the room journal immediately with a unique request ID, without moving ownership or changing the active turn's context snapshot. Before a reply commits, check for newer human messages. If any exist, return them for explicit acknowledgment and review under the same turn, then accept the revised reply. This check and commit share the room lock. The latest explicit human Reply next choice overrides the AI's nomination at the next handoff, subject to pause, required human input, the four-turn cap and recipient availability. Mid-turn messages do not reset the cap. At the cap, the choice waits for an explicit continuation. Sending does not interrupt a tool call or undo edits already made. The UI says when input is saved and when the current AI has read it. Prompt counts describe intended build rounds, not a completion guarantee. The extra scheduling logic makes P1 low to medium risk.

Proposal 3 · Lives in your apps

A short test decides whether we build it

What the test must prove

Semaphore can open a chat for each AI

That chat gives its first reply

It wakes up again for later turns

App permission prompts still reach you

It recovers after an app restart

Replies match the right chat and turn

What we already know

Plugin or MCP tools can hide the commands. Waking an idle chat also needs support from its host app.

Codex's app-server can start threads and turns for its own clients. That doesn't show it can drive a chat already open in the app.

Claude's private messaging socket stays experimental, and no open chat is ever resumed from a second process.

A test, then a few prompts

Higher, app-dependent

14

Each conversation gets its own native chat per AI, so context and receipts stay separate. The talking stick only covers one room, so two conversations editing the same folder would need a shared write lock or separate worktrees. Official Codex app-server documentation supports thread/start followed by turn/start for custom clients: https://learn.chatgpt.com/docs/app-server (checked 23 September 2026). This does not establish access to the runtime of an already-open desktop chat. The private Claude socket is an unverified integration lead. No daemon settings were changed during this review.
